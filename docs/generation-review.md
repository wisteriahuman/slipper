# 生成の評価（2026-09-26）

## 実装したこと

手法の無作為抽出を外し、内容と画像から3案の狙い・根拠・具体的な見せ方を先に選ぶ。補助手法との組み合わせを記録し、カードで選んだ理由を見られるようにした。

カタログ全38項目に必要な材料・成立条件・失敗例・組み合わせ候補を追加した。ペチャクチャは20枚×20秒という定義に直し、時間制御が実装されるまでは自動選択から外す。原典そのものと発表への応用を、説明で区別する。全出典を再調査したわけではない。

連続の検査と編集を手法ごとに分けた。拡大縮小と場面転換を許し、寄る・引くでは同じ対象が実際に拡大縮小したかと縦横比を検査する。Googleへの書き戻しでも素材の回転・反転を保つ。

同じReact部品とCSSで案を描画し、文字のはみ出しをDOMで検査する。最後に描画した案と提出内容の一致を確認する。作成側が画像を見直した後、別のAI呼び出しで画像・根拠・狙いを照合し、明確な不一致を修正へ戻す。後者の見直しは最大3回。見直しに失敗した案を自動的に合格扱いしない。

流れの段の順序と、既存の連続の分断も検査する。流れの採用は構成の下書きであり、新規・統合ページの完成までは作らないことをUIに明示した。

## 画像とデータを確認して残った問題

- 数値比較の計画に「短縮の理由を読み取らせる」という狙いが含まれた。入力項目の事前確認が原因と検証された資料ではない。スライドには未検証の注記があっても、狙いの断定が強すぎる。
- スロープグラフの狙いが「二本の長さで比べる」という表現になり、出来上がった二点を線で結ぶ図と一致しない。
- 段階的追加の狙いは申請→確認→支払いを一段ずつ理解させることだったが、最初のコマで三つとも見えていた。後続では例外の説明が追加されている。形式的な連続検査だけではこの不一致を検出できない。
- 2つの立場を分けた案は読みやすく整理されているが、場面の実物を見せる表現には至っていない。素材機能の必要性を判断する材料として残す。

これを受け、計画と見た目の自己点検だけで受理せず、別の呼び出しで主張・根拠・実際の表現の対応を確認する段階を追加した。指摘に応じて、狙いの強すぎる言い方も直せる。

## 検証と限界

- 自動テストでは、拡大縮小・場面転換・逆順のABT・既存連続の分断・未描画の提出・描画後の変更・修正要求後の再提出・見直し結果の保存を確認。
- MCPの実通信で、プレビューには確認番号が不要で、提出時には必要であることを確認。
- Electronの実描画で日本語の文字切れを検出。
- 別のAIによる見直しは、制御した応答で修正要求→再描画→受理を検証した。利用上限のため実AIでは未検証。
- Google Slidesへの実際の書き戻し・その画像との比較は未実施。パネル描画とGoogle側のフォントや改行には差が残り得る。
- 今回は合成した2題材・各1回の観察。未知の手法との出会い、聞き手の理解、採用率が改善したことまでは実証していない。
