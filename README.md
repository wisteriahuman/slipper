# Slipper

思いつかなかった伝え方を探して、Google Slides の資料を育てる制作支援アプリ（macOS・Electron）。

左に本物の Google Slides、右に Slipper のパネルを置きます。**どちらでも同じ資料を編集できます。** Google Slides だけを使う共同編集者も、普段どおり作業を続けられます。

- **編集する**：既存の文字や図を選択して直し、同じページに反映します。選んだ文章だけをAIと磨くこともできます。
- **別案を探す**：AIに伝え方の異なる案を3つ出してもらい、比べて手を入れ、元のページの直後に追加します。この操作では元のページを変更しません。

設計（要件定義・ペルソナ・業務フロー・システム構成・MCP ツール仕様・ER 図・ADR）は、Touchstone の設計プロジェクト「slipper（スライド制作支援）」にあります。

## 必要なもの

- macOS、Node.js 22 以上
- ログイン済みの [Claude Code](https://claude.com/claude-code)（`claude` コマンド）。AI の API キーは使いません
- 普段のブラウザ（Arc か Google Chrome）で Google にログインしていること
- Google Cloud の「デスクトップ アプリ」型の OAuth クライアント（下記）

## 起動

```sh
npm install
npm run dev
```

右パネルの「準備」に沿って進めます。

1. **Google のログインを取り込む**：アプリ内では Google にログインできないため、普段のブラウザから google.com の Cookie だけを取り込みます。キーチェーンの確認で「許可」を押します
2. **OAuth クライアントを設定する**：下記で作った JSON を選びます
3. **Google Slides API に接続する**：普段のブラウザで許可画面が開きます

## Google Cloud の設定

1. Slipper 用のプロジェクトを作り、Google Slides API を有効にします
2. Google Auth Platform で同意画面を設定し、テストユーザーに自分を追加します
3. OAuth クライアントを「デスクトップ アプリ」で作り、JSON をダウンロードします

権限の範囲は `https://www.googleapis.com/auth/presentations`（自分の資料の読み書き）です。選んだファイルだけに絞る `drive.file` では、左で開いている資料を読めない（Google Picker で選んだファイルか、アプリが作ったファイルに限られる）ため、資料ごとに選び直す手間を避けてこちらにしました。

OAuth アプリが「テスト」公開のままだと、Google の仕様でリフレッシュトークンが7日で失効します。その場合は「接続する」をもう一度押してください。

## AI の呼び方

### 選んだ文章と、同じページの編集

「編集する」では、Google側のページ画像から要素を選択します。文字の変更、対応する要素のドラッグ移動・位置と大きさの指定、複数要素の整列・等間隔配置ができます。Google側の変更は8秒ごととウィンドウへ戻ったときに確認します。「最新を確認」でも取得できます。

- 編集はまず下書きになります。下書きと編集開始時の内容は端末に保存され、ページやタブの切り替え・アプリの再起動後も復元します。
- 「同じページに反映」で、変更した文字・配置だけを既存のGoogle要素に適用します。文字や図は編集可能なままで、要素のIDも保ちます。
- 他の人が文章を変え、自分が配置を変えた場合は、両方を残します。同じ文章や配置が双方で変わった場合は、現在の内容と下書きを比較して選びます。比較中にさらに変更されても、反映時に再確認します。
- 「一つ戻す」は下書きを戻します。「直前の反映を取り消す」は共有資料への変更を戻します。後者は、その後に同じ箇所が編集されていれば止まります。
- 「この文章の別案を見る」は、選択文章とページの文章、保存済みの「誰に・何を」をClaude Codeへ送ります。数値の保持を検査し、別の呼び出しで条件・意味・手順の順序を照合した候補を表示します。候補を選んでも、共有資料への反映はまだ行いません。

画像はGoogle側の表示で、変更後の配置は点線、文章の変更は差分で確認します。下書きの完成描画を再現するものではありません。グループ内・表のセル・特殊な要素や詳細な書式はGoogle Slides側で編集します。文章の変更範囲の書式はGoogleの挿入規則に従い、削除した部分の細かな書式まで取り消しで復元する機能はありません。

設計と検証の詳細は [両側からの編集](docs/collaborative-editing.md) を参照してください。

### ページ全体の別案

「別の伝え方を見る」を押すと、画面なしの Claude Code（`claude -p`）を使い、次の順に進めます。

1. 元の画像と内容、「誰に・何を」から、狙い・根拠・具体的な見せ方の異なる3案をまとめて考えます。手法は内容に合わせて選びます。
2. 選んだ3案を並行して作ります。主な手法に、補助の手法を最大2つ組み合わせられます。
3. `preview_variant` でパネルと同じ React コンポーネントを画像にし、文字切れを測定します。AI は画像を見て必要な修正を行います。
4. 提出前に別の Claude Code 呼び出しが、画像・元の材料・狙いを照合します。明確な不一致があれば作成側へ戻します。見直しは1案につき最大3回です。

描画した内容を変更すると、提出用の確認番号は無効になります。描画・見直しを省略した案は受け取りません。これは品質の保証や聞き手による評価ではありません。Google Slides 側のフォント・改行との完全一致も保証しません。

AI は組み込みのツールを持たず（`--tools ""`）、Slipper の MCP サーバー（`127.0.0.1`、起動ごとのトークンで認証）を使います。Google Slides への書き込みは利用者の採用操作で行います。

「標準」は思考量 medium、「じっくり」は high です。計画と画像の見直しが入るため、従来の15秒という目安は使いません。待ち時間・AI利用量は増えます。

## 手法と連続の扱い

カタログはページ用25種類・流れ用13種類です。原理・視覚表現・連続演出・話の構造・発表形式を区別し、必要な材料、成立条件、避ける失敗、組み合わせ候補を持ちます。ペチャクチャは20枚×20秒の形式として記載し、時間制御がない現状では自動選択しません。

- 段階的に足す・注目を移す：共通要素の位置と大きさを固定
- 寄る・引く：同じ対象を追跡し、縦横比を保って拡大縮小
- Lessig・区切って見せる・問いと答え：場面転換を許可
- データを動かす：共通要素を残し、データの移動を許可。尺度の妥当性は画像の見直しで確認

手直しでも固定する連続だけ位置・大きさを全コマへ反映します。流れの案は段の存在と順序、既存の連続の分断を検査します。

## 流れの採用範囲

「この流れで構成の下書きを作る」は、元の資料を複製して並べ替えます。新規ページは制作指示を置き、統合ページは最初の元ページを土台として使います。完成した新規・統合ページの自動制作はまだ行いません。

## 生成の評価

`npm run evaluate:generation` は合成した4題材をローカルで描画し、文字切れの検出を確認します。Googleへの接続や書き込みは行いません。

実際の Claude Code で生成まで評価する場合（利用量を消費します）：

```sh
SLIPPER_EVAL_LIVE=1 npm run evaluate:generation
# 題材を選んで再実行
SLIPPER_EVAL_LIVE=1 SLIPPER_EVAL_CASES=operation,proposal npm run evaluate:generation
```

出力先は `/tmp/slipper-generation-eval`。`SLIPPER_EVAL_OUTPUT` で変更できます。実施した範囲と残る問題は [生成の評価記録](docs/generation-review.md) を参照してください。

既知の案を再生成せず検証側に渡す場合は、`{"variant": <保存した案>, "expect": "accept" または "reject"}` のJSONを用意し、`SLIPPER_EVAL_REPLAY` にそのパスを指定します。`SLIPPER_EVAL_CASES` で元の題材を1つ選びます。結果と指摘は出力先の `replay.json` に保存され、期待と違えば終了コード1になります。

Google側の描画も比較する場合は、保存済みの生成結果と既存のGoogle接続を使います。次のコマンドは **検証専用の新しい資料を1つ作成** し、その中に案を書き戻します。資料のURLと各ページのGoogle画像・パネル画像を `/tmp/slipper-writeback-eval` に保存します。

```sh
SLIPPER_EVAL_GOOGLE=1 SLIPPER_EVAL_OUTPUT=/tmp/slipper-generation-reviewed node scripts/evaluate-writeback.mjs
```

`SLIPPER_WRITEBACK_OUTPUT` で書き戻し結果の保存先を変更できます。画像やグループ素材を含む実資料の再現性は、この合成データの検証には含まれません。

## 資料内の素材を使う

「このページ」の「資料内の素材を使う」で素材を読み込むと、資料内の画像・グラフと各ページ全体の画像が一覧になります。選んだ素材（最大6件）は、別のページの案でも使えます。複雑な図や表は、ラベルごと見せるためにページ全体を選びます。

- 選択は資料ごとに保存されます。案には使った素材の画像と出典ページ・文脈を保存するので、後で選択を変えても過去の案の見た目は変わりません。
- 採用時は素材元を取得し直し、案を作った時点から変わっていれば書き戻しを止めます。古い画像のまま追加しないためです。
- Google Slides には画像として追加します。ページ全体の素材は、元のページの見た目の画像になり、中の文字は編集できません。

## 素材ライブラリ

「素材ライブラリ」タブの素材は、どの資料の案でも使えます。AI は案を作るとき、`search_library` で内容に合う素材を探し、返された画像を見て使うかを決めます。

- **同梱の素材**：Lucide のアイコン（ISC、`lucide-static` パッケージ）と、Open Peeps の人物イラスト91点（CC0、`resources/library/open-peeps`）。クレジットは不要です。Open Peeps のうち、刃物を持つ2点は除いています。
- **取り込んだ素材**：自分でダウンロードした画像（PNG・JPEG・GIF・SVG）を取り込めます。出典のURL・ライセンス・クレジットの要否と表記文・点数制限のメモを記録し、「利用条件を確認して保存」するまで、AI の候補には入りません。
- **クレジット**：クレジットが必要な素材を含む案を採用すると、資料末尾の「クレジット」ページ（Slipper が作るページ）に表記を追記します。規約が使った場所への表記を求める場合は、そのページの下部にも小さく入れます。点数制限のメモは、採用時に表示します。
- **Google Slides への追加**：画像はドライブに一時的にアップロードし、追加する数秒の間だけリンク共有にして、追加後に削除します（Google Slides が公開URLからしか画像を取り込めないため）。機密の画像は取り込まないでください。SVG は PNG に変換してから渡します。
- **アイコンの色**：アイコンは既定で濃い灰色です。案の中でテーマ色を指定すると、その色で Google Slides に追加します（色の意味の規則は文字と同じ）。人物イラストの色は変えられません。
- **検索**：日本語の語は、スライドでよく使う語の辞書（`src/main/library-words.ts`）で英語のアイコン名に展開して探します。検索精度は `test/icon-search.test.ts` で測っています。

素材の規約の調査と決定事項は [要件](docs/asset-library-requirements.md) を参照してください。

## 色の扱い

色は資料のテーマ色を名前で参照します。**意味が決まっていない強調色は使わせません**。「誰に・何を」の画面で強調色に意味（例：「いま空いている」）を書くと、AI はその意味の場所にだけ、その色を使います。決めていない間は、文字の大きさ・太さ・余白で強調します。

## 開発

```sh
npm test          # vitest
npm run typecheck
npm run build
```

- `src/main`：メインプロセス（アプリ内ブラウザ、Cookie の取り込み、OAuth、Slides API、MCP サーバー、Claude Code の起動、SQLite）
- `src/preload`：パネルに渡す呼び出しの一覧
- `src/renderer`：右パネル（React）
- `src/shared`：要素の形・検査・座標・色の規則
- `prototype/`：最初の試作（事前に用意した案を比べる版）
- `spikes/`：技術検証（アプリ内ブラウザ、Claude Code と MCP）
