# Slipper

Google Slidesを使う制作支援アプリの、最初のローカル試作。伝え方が異なる案を比較し、採用した案を直接編集します。**デザインの一つひとつに理由を持たせる**ことを重視しています。色は意味で指定し、各案には「なぜこのデザインか」を付け、デッキの決まりごとはlintで検査します。

アプリ本体は特定の資料に依存しません。中身は「デッキ」というデータとして `public/decks/` に置きます。同梱の `furifuru.js` は、サービス説明資料を題材にした例です。

## 構成

- `public/model.js` — 汎用エンジン。要素の移動・固定、ルールの検査、Google Slidesへの変換
- `public/app.js` — 編集画面。`?deck=<名前>` で `public/decks/<名前>.js` を読み込む（省略時は例のデッキ）
- `public/decks/*.js` — デッキ（純粋なデータ）
  - `colors`: 色の役割。`{役割: {hex, name, means}}` の形で、要素は色コードではなく役割名で色を指定する
  - `rules`: 決まりごとと理由。`check` を書くと編集中に検査される（`{bg}` / `{role, notBefore}` / `{role, max}`）
  - `pages`: ページごとの表現案と、案ごとの理由 `rationale: [{ids, what, why}]`

## 起動

Node.js 20以上が必要です。外部npmパッケージのインストールは不要です。

```sh
npm run dev
```

http://localhost:4173 を開いてください。`PORT=4174 npm run dev` でポートを変更できます。

## 試せること

- ページごとに、場面・時間・構造など異なる表現のサンプルを比較して採用
- 各案の「なぜ、このデザインか」を読む（理由にカーソルを合わせると対象の要素が光る）
- 色は色コードではなく意味（紙・墨・控え・線・空き）で指定。デッキの決まりごとに反した配色は警告される
- 要素の選択、ドラッグ、矢印キーによる移動（Shiftで10px）
- テキスト、文字サイズの編集と、意味による色の選択
- 要素の固定、位置とサイズの変更をプレビューして採用
- 元に戻す／やり直す（セッション内）、ブラウザ内保存、JSON保存・読み込み
- Google OAuth設定後、新しいGoogle Slidesへ全ページを編集可能な文字・図形として書き出し

表現案はデッキに書かれたサンプルです。AI生成、意図メモに基づく生成、周囲を考慮した自動再配置、Google Slidesからの取り込み・双方向同期・共同編集への追従は未実装です。元の参考資料は変更しません。元のスライドの完全なコピーではなく、会話で確認した内容から作った表現スタディです。

## Google Slidesの初期設定

1. Google Cloudでプロジェクトを作り、Google Slides APIを有効化します。
2. Google Auth Platformで同意画面を設定します。テスト公開では自分をテストユーザーに追加します。
3. OAuthクライアントを「ウェブ アプリケーション」で作り、承認済みJavaScript生成元に `http://localhost:4173` を登録します。別ポートを使う場合はその生成元も登録します。
4. アプリの「Google Slidesへ」でクライアントIDを入力します。クライアントシークレットは不要です。
5. ライブラリ準備後に認証ボタンを押し、Googleの許可画面を操作します。

スコープは `https://www.googleapis.com/auth/drive.file`。新しく作成する資料へのアクセスに使います。アクセストークンはメモリ内のみで使い、localStorageやサーバーに保存しません。クライアントIDと編集データのみブラウザ内に保存します。画面のサンプルはGoogleに自動送信しません。

Googleへの書き出しはREST APIによる実装ですが、OAuthクライアント未提供のため実アカウントでの書き出しは未検証です。Google Slides上ではフォントの代替、テキストボックスの内部余白、改行、角丸の違いが生じる可能性があります。失敗時は作成済み資料へのリンクを示します。新規作成だけ成功した場合、空の資料が残ります。

参照: [Googleのトークンモデル](https://developers.google.com/identity/oauth2/web/guides/use-token-model)、[Slides batchUpdate](https://developers.google.com/workspace/slides/api/reference/rest/v1/presentations/batchUpdate)

## 確認

```sh
npm test
```

ネイティブのNodeテストで、サンプルの境界、固定要素、移動時の境界処理、Google Slidesリクエストの構造に加え、デザインの説明責任（全要素が定義済みの色の役割を使う、アクセント色の使用には必ず理由がある、理由が実在する要素を指す、ページをまたぐ要素が同じ形を保つ）を確認します。見た目と操作はブラウザで別途確認してください。

最初の評価では「自分では選ばなかった表現を見つけられるか」「意図した位置や大きさに直せるか」「手直しを残したまま進められるか」を実際に触って確かめます。
